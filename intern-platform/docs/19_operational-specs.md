## 1. 審査基準 v1（ルーブリック）

### 1-1. 原則

- 合否は **F2実績(30点) + F3課題(40点) + F4行動(30点) = 100点満点**。学歴(F1)と適性検査スコアは合否に使わない（表示・マッチング用途のみ）
- **合格ライン: 60点以上 かつ F3が15点以上**。55〜59点のボーダーは人力レビュー必須
- 目標通過率50%前後。招待経由も同一基準（免除なし）
- 低学年は実績が薄い前提のため、F2は「規模」でなく「行動の質」を採点し、F4（プロセス中の行動）で実績のない優秀層を拾う

### 1-2. 採点表

| 軸 | 項目 | 配点 | 見るもの |
|---|---|---|---|
| **F2 実績** | 具体性 | 10 | 何を・どうやったかを数字/成果物/固有名詞で語れるか（肩書だけは0点） |
| | 主体性の痕跡 | 10 | 自分で始めた/与えられた役割を超えた行動があるか |
| | 継続性 | 10 | 6ヶ月以上続けた活動が1つ以上あるか（勉強・部活・バイト・創作なんでも可） |
| **F3 課題**（職種別15分） | 論理構成 | 15 | 結論→根拠の構造。ケース: 分解の筋 / ライティング: 構成 / コード: 動くこと+可読性 |
| | 着眼・具体性 | 15 | 自分の頭で考えた跡（一般論の羅列は減点） |
| | 伝わりやすさ | 10 | 読み手への配慮（分量・見出し・言葉選び） |
| **F4 行動** | 期限・指示遵守 | 10 | 期限内提出・設問の指示どおりか |
| | 記入の丁寧さ | 10 | 誤字/空欄/使い回しの跡。丁寧さは入社後の仕事ぶりの最良の代理変数 |
| | 自分の言葉率 | 10 | ヒアリング回答が定型文でなく具体的か（AI丸写しはF4で検出・減点） |

### 1-3. 運用

- **AI一次採点（Claude・ルーブリックプロンプト）→ 人力確定**。最初の50人は全件人力採点し、AI採点との相関を確認してからAI一次に移行（キャリブレーション）。以後も20%抜き打ち監査
- 課題は職種別3種（ビジネスケース簡易版 / ライティング / コード）から学生が選択。設問は月次ローテーション（模範解答の流通対策）
- 不合格者: **全員に「強み1つ+改善点2つ」のフィードバック**+再挑戦（課題の再提出は1回まで即時可、以後は翌学期）
- 公開する情報: 審査の観点（上の3軸）と通過率。配点の詳細・設問は非公開
- 較正: 通過者のその後（面談実施率・稼働開始率・30日継続率）を軸ごとに追い、四半期ごとに配点を見直す（審査スコアと現場成果の相関が審査の品質KPI）

## 2. 新卒転換フィー 条件表（完全版）

### 2-1. 発生条件の定義

> 当社経由で稼働開始したインターン生（またはマッチ提示を受けた学生）が、**同一企業（グループ会社含む）の新卒採用に内定承諾した時点**で発生。請求は内定承諾の翌月末（新卒紹介の標準タイミングに準拠）。

### 2-2. 金額表

| 条件（稼働開始日→内定承諾日の期間） | フィー | 根拠 |
|---|---|---|
| 稼働6ヶ月未満で内定承諾 | **35万円** | ほぼ見極めコストなしで新卒獲得（紹介予定派遣の相場60〜140万の半額以下） |
| 稼働6〜12ヶ月 | **25万円** | 企業の育成投資を減額で還元（逓減=「育てた分だけ安い」） |
| 稼働12ヶ月超 | **15万円** | 長期育成の労に報いる最低区分 |
| **学生の卒業後**（卒業年度の3月末を経過） | **0円（自動消滅）** | 「転換を妨げない」保証。企業がインターンのまま塩漬けにするインセンティブを消す |
| 稼働実績なしの直接採用（迂回） | **35万円** | マッチ提示から1年以内の直接新卒採用は稼働ゼロでも対象（迂回防止条項） |

## 3. 招待設計 v1 — 「誘われない」を潰すバイラルループ設計

### 3-1. 課題認識

「招待枠3つ」を置くだけでは誘わない。誘わない理由は ①誘う口実がない（マルチ勧誘っぽくて気まずい） ②誘うメリットがない ③送る文面を考えるのが面倒 ④いつ誘えばいいか分からない。4つすべてに設計を当てる。

### 3-2. ①口実 → 招待を「推薦」に変える（設計の核）

- 招待の名称・体験を**「推薦」**にする。招待リンクは汎用URLではなく、**招待者の名前入りの推薦状**（「◯◯さんがあなたを推薦しました」+推薦理由をテンプレから選択: 「行動力がある」「文章がうまい」等）
- 誘う行為が「マルチの勧誘」ではなく**「友人の良さを認めて機会を渡す行為」**になる。受け取る側は選考の場に「推薦されて」入る＝気持ちよく、招待者の面目も立つ
- 落ちても関係が壊れない保険: 招待経由の不合格者にもフィードバックが返る（「受けて損」がない）ことを推薦状に明記

### 3-3. ②実利 → 控えめな報酬+ステータス

- 金銭: 推薦した学生が**稼働開始した時点**で招待者にAmazonギフト3,000円（合格時ではなく稼働時=質の担保・乱発防止）。金額はあえて控えめ（金目当ての乱発は質を毀損する）
- ステータス: 「推薦者バッジ」+推薦実績が本人の実績書に載る（「人を見る目」は企業に見せられる実力の一部）。推薦→稼働の実績が貯まると招待枠が3→5に拡大

### 3-4. ③摩擦 → 文面を考えさせない

- 推薦状発行時に**LINEでそのまま送れる文面を3トーン（まじめ/カジュアル/ひとこと）自動生成**。1タップコピー
- 例（カジュアル）: 「これ審査制のインターンサービスなんだけど、◯◯って行動力あるから推薦しといた。審査通ると書類なしで面談確約になるやつ。落ちてもフィードバック返ってくるから損はないと思う → [リンク]」

### 3-5. ④タイミング → 高揚の瞬間にだけ促す

| トリガー | 促し方 |
|---|---|
| 合格直後（最大の高揚） | 合格画面の直後に「あなたが推薦できる枠は3つ」画面（スキップ可） |
| 初マッチ提示時 | 「同じ興味の友達がいたら推薦を」 |
| 稼働開始時 | 「一緒に頑張る仲間を」 |
| （分離）タイプカードのシェア | 招待とは別動線。シェア→公開ティザー診断→エントリー（不特定多数向けはこちらが担う） |

- 常時バナーは置かない（せっつくと「マルチ感」が復活する）

### 3-6. 計測とキル基準

- KPI: 招待送信率（合格者のうち1通以上送った割合・目標40%）/ 招待→審査申込転換（目標30%）/ 2巡目継続（招待経由の合格者がさらに招待する率）
- **送信率20%未満が1ヶ月続いたら「推薦」フレーミングとトリガーを再設計**（インセンティブ増額はその後。金で解決しにいかない）
- 期限14日・月3枠の希少性表示。招待経由も審査は同一基準（3-2の信頼の前提）

## 4. 企業が適性検査で「合う/合わない」を決める観点

### 4-1. 原則: 企業は検査を「読まない」。2つの質問に答えるだけ

企業側にBig5や生スコアの解釈をさせない。企業がやるのは求人作成時の2つの入力のみ:

1. **「この仕事で成果を出すにはどんな持ち味が必要か」** → 30特性（採用担当が普段使う言葉）から最大8個選択+特に重要な数個に重み。画面に**職種別のおすすめガイド**を表示: チーム協働が多い→協調系（チームワークとの相関が実証済み）/ 営業・対人→外向・交渉系 / 学習・変化が多い→開放系 / どの仕事でも→誠実系（唯一全職種で効く予測子）——メタ分析根拠つきの推奨（実装仕様書6.36）
2. **「うちは何を提供できるか」** → 10項目（成長機会・裁量・チーム・評価・専門性・待遇・両立…）を1〜5で正直に申告

### 4-2. システムが「合う」を判定する2つの観点（企業に見せる説明そのまま）

- **観点A: 仕事が求めるものを、その学生が持っているか**（求める特性×学生の特性推定）。不足だけを減点し、超過は減点しない（「求める以上に社交的」はマイナスではない）
- **観点B: その学生が求めるものを、この仕事が提供できるか**（学生の志向TOP×提供環境）。**早期離脱の最大要因は実はこちら**（満足度への効きは観点Aより強いという研究知見）で、「企業には合うが学生の望みと違う」組は総合スコアが上がらない仕組み（調和平均）
- 例: 営業求人で「交渉力(重)・社交性(重)・継続力」+提供「成長5・裁量4・待遇2」→ 社交80pctile・成長重視の学生Xは提示される / 特性が同等でも待遇最重視の学生Yは提示されない（入社後不満の芽を入口で摘む）

### 4-3. 企業に見えるもの / 見えないもの

| 見える | 見えない |
|---|---|
| 適合度（プール内の相対位置）+根拠特性トップ3+ギャップ | Big5の生スコア・詳細パーセンタイル |
| 強み特性バッジ・志向TOP3・行動信頼スコア | 「正直に言うと」（本人のみ）・回答内容 |
| AI推薦文（志向と求人の接点を言語化） | 不合格者・プールの他の学生 |

### 4-4. 一番大事な運用原則

**適合度は「会う順番」であって「会わない理由」ではない。** そもそも企業には適合したマッチ2〜5件しか提示されないため、企業が検査結果で学生を「切る」場面自体が発生しない。面談確約（5営業日以内・原則実施）は適合度の高低にかかわらず維持される。検査は選別ツールではなくミスマッチ防止装置——この位置づけは規約・企業向けガイドに明記する（「足切りに使わない」原則の企業側への実装）。
