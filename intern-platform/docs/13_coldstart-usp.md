## 1. 知名度ゼロ問題への正直な回答 — 「審査ブランド」は初期の集客装置にしない

ご指摘のとおり。NewsPicks Student Picker・外資就活アカデミア・FactLogicの「審査に応募が殺到する」構造は、**背後のブランドの威光があって初めて成立する**。無名の新サービスが「審査制です」と言っても、落ちるコストを払ってまで応募する理由がない。12_gtm-plan.md §3の設計はこの点で順序が逆だった。

### 順序を逆転する: 「実利 → 実績 → 審査ブランド」

| 段階 | 何で集めるか | 審査の位置づけ |
|---|---|---|
| **0〜3ヶ月**（無名期） | **実利**: 「この企業に、書類選考なしで会える」（供給先行で確保した面談確約求人を見せる）+ 1期生の一本釣り + 紹介 | 審査は「入会条件」として静かに実施するだけ。宣伝の主語にしない |
| 3〜9ヶ月 | 実利 + **実績の可視化**: 「◯人が面談確約→◯人が稼働開始」「合格者の顔ぶれ」 | 「審査を通った人だけの場」を語り始める |
| 9ヶ月〜 | 実利 + 実績 + **審査ブランド**: 倍率・合格者プロフィール公開が効き始める | 集客装置として機能（ここで初めてNewsPicks型になる） |

### 無名期に借りられる信用（ブランドの代替物）

1. **掲載企業の顔ぶれ**（最重要）: 学生が信用するのはサービス名ではなく「会える企業のロゴと求人の中身」。→ **企業側を先に立ち上げる**（§4のカレンダー修正）
2. **1期生の顔ぶれ**: 一本釣りした実績ある学生の実名・所属（本人同意の上）
3. **アドバイザーの顔ぶれ**: 起業家・人事・OBOG 5〜10人の実名
4. **ツナカレ/PieceTimesの実在**: 「ツナカレインターン」のサブブランド化（§3）で、運営実体のある会社のサービスという最低限の信用を初日から持てる

## 2. 学生向けUSPの確定 — 「なぜ学生は当社を使うのか」

### 市場の痛み（調査済みの事実から）

長期インターンの選考合格率は**5〜10%**。学生は平均4〜5社に応募し、その大半で落ちる。つまり既存媒体（ゼロワン・Renew・Wantedly）が学生に提供しているのは「たくさんの求人に、ゼロから応募して、ほぼ落ちる」体験。低学年ならなおさら実績がなく落ちる。

### USP: **「応募して落ちまくる構造」を消す**

> **ツナカレインターン = 審査に1回通れば、企業の書類選考を飛ばして面談が確約される場所。落ちても、選考フィードバックと再挑戦が残る場所。**

| 学生への提供価値 | 中身 | 競合に無い理由 |
|---|---|---|
| **① 共通選考パス（面談確約）** | 入会審査（5軸・12_gtm-plan §2）に1回通れば、掲載企業へは**書類選考なし・面談確約**でマッチ提示2〜3件。「10社応募して9社落ちる」が「1回の審査で2〜3社と確実に会える」に変わる | 媒体は審査をしていないので企業が書類選考せざるを得ない。エージェントは人力面談が必要でスケールしない。**審査制×面談レスの当社だけが「面談確約」を企業に約束させられる**（企業側も審査済み+推薦文付きなら選考コストが下がるので合理的に応じられる） |
| **② 落ちても得る（選考フィードバック）** | 審査不合格者全員に課題フィードバック+再挑戦パス。就活市場で選考フィードバックはほぼ存在しない | 競合の不合格者は「サイレントお祈り」される。フィードバックは審査を内製しているから返せる |
| **③ 実績書の自動蓄積** | 審査課題・実務経験・企業評価が「実績プロフィール」として蓄積され、AIがガクチカ・ESの形に言語化。**新卒就活にそのまま持っていける資産**になる | 媒体のプロフィールは応募のための入力欄でしかない。当社は新卒（ツナカレ）まで一気通貫だから資産化する意味がある |
| **④ 低学年から入れて、新卒まで続く** | 1年生から入会可。3年になればツナカレ経由で新卒スカウト・紹介に接続（スカウトDB統合・§3） | 新卒スカウト勢（OfferBox等）は実質3年生から。インターン媒体は新卒側の出口を持たない |
| **⑤ 期待値の一致** | 構造化求人（採用目的開示・合わない人の明示）+ 志向マッチ提示 | ミスマッチ解消設計はエコノミクスの武器（09修正1）だが、学生向けにも「変な企業に当たらない」安心材料として効く |

**一言で**: 既存サイトが「求人を探す場所」なのに対し、ツナカレインターンは**「一度審査を通れば、企業の方から確実に会ってくれて、経験が新卒就活の武器として積み上がる場所」**。訴求の一番手は①（面談確約）、二番手は③（実績書）。

### ①を成立させる企業側の約束（要件への追加）

- 掲載条件に「プールからのマッチ提示に対しては**5営業日以内に面談可否を回答し、原則面談を実施する**」を含める（面談確約パスの担保）
- 企業側メリットとして明示: 書類選考不要・推薦文付き・行動信頼スコア付き・ドタキャン抑制済み → 選考コスト削減

## 3. ブランド決定とスカウトDB統合 — 「ツナカレインターン」

**決定: サブブランド「ツナカレインターン」で確定**（08_brand.md の推奨どおり。§1の「無名期の信用」問題にも最良の解）。

### スカウトDBはツナカレと共通基盤にする（Phase 2 の中核仕様に格上げ）

| 設計 | 内容 |
|---|---|
| **共通ID・共通プロフィール** | 学生は1つのプロフィール（審査結果・実績書・部活/団体所属・志向）を持ち、インターン期も新卒期も同じIDで使い続ける。「一生モノのキャリアプロフィール」 |
| **企業側は1つの管理画面** | ツナカレ（部活接点・新卒）とツナカレインターンを同一アカウントで利用。スカウトはインターン対象/新卒対象を切り替えて送信 |
| **スカウト課金の整理** | インターンスカウト→採用: プランA/B の成果報酬（12_gtm-plan §1）/ 新卒スカウト→採用: ツナカレ新卒側の料金。**11_revised-model の料金ラダーに「スカウト経由」を明記**し、カニバリの余地を残さない |
| **部活単位データとの接続** | ツナカレ既存の部活単位登録は、部員が個人IDを作った時点で個人プロフィールに紐付く。ツナカレインターンが「個人単位登録の受け皿」になる（当初構想どおり） |
| 実装順序 | Phase 1: 共通IDを見据えたスキーマでツナカレインターン単体を構築（認証・プロフィールを独立させない設計）→ Phase 2: 企業検索・スカウト送信を解放（プール500人以上が条件）→ Phase 3: ツナカレ本体の企業アカウントと統合 |

これにより学生向けUSP④が完成する: **「ツナカレインターンに入る＝3年後の新卒スカウトまで含めたキャリア基盤に乗る」**。

## 4. カレンダー修正（供給先行）

12_gtm-plan §3-3 を次のとおり修正:

| 月 | 修正後のアクション |
|---|---|
| **9月** | **企業を先に**: アウトリーチ週50社を最優先（「審査済み学生・書類選考なし・面談確約」の掲載条件で）→ 9月末までに面談確約求人10件 / 並行してアドバイザー5人の招聘・1期生候補のリストアップ |
| **10月** | 求人20件を「会える企業一覧」としてLP公開 → **これを見せて**1期生20人を一本釣り / 学生団体提携交渉（ギブ=会員限定の面談確約枠） |
| **11月** | 11/2 許可 → マッチ提示・面談確約の運用開始 / 初決定 / 1期生の招待枠開始 |
| 12月〜 | 12_gtm-plan §3-3 のとおり（実績可視化→審査コンテンツ化は3ヶ月後ろ倒しで9ヶ月目〜） |

集客目標の修正: 無名期（9〜11月）の申込目標を月20〜40件に引き下げ（実利+一本釣り+紹介のみで達成可能な水準）、月100件の達成時期を2月→**4月（春休み・新学期の低学年行動期）**に後ろ倒し。初年度決定数のレンジ（40〜60件）は、決定率の高い実利集客が先行するため維持する。
