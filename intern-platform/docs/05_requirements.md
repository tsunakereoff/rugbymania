## 1. サービスコンセプト

> **「仕事のリアルが分かるから、ミスマッチが起きない長期インターン選び」**

学生は「知っている企業か」「求人が面白そうか」で短期集中的に判断してしまい、
企業は「将来の新卒採用・戦力化」を期待する——この期待値ギャップを、
**応募前に仕事と企業のリアルな解像度を上げる**こと、および
**学生側の志向を言語化してから応募させる**ことで埋める。

### 提供価値（学生）
1. 求人票では分からない「仕事のリアル」（任される業務の具体、1日の流れ、先輩インターン生の体験談・口コミ）が応募前に分かる
2. 軽量な自己分析（志向性診断）で「自分が何を求めてインターンをするのか」を言語化してから選べる
3. 部活・課外活動と両立できる条件（週2〜、リモート可等）で探せる

### 提供価値（企業）
1. 掲載無料・完全成果報酬で、リスクなく長期インターン採用を始められる
2. 「インターン採用の目的」（新卒採用の入口か、即戦力か）を構造化して開示するため、期待値の合った学生だけが応募してくる
3. セルフサーブの応募者管理で、営業や担当者とのやり取りなしに採用まで完結する

## 2. フェーズ計画

初期投資を抑えつつ「成果報酬が発生する検証」を最速で回すため、3フェーズで構築する。
**Phase 0 は開発を最小化し、オペレーションで検証する**（コンシェルジュ型MVP）。

| フェーズ | 期間目安 | 内容 | 検証すること |
|---|---|---|---|
| **Phase 0: メディア + 手動マッチング** | 〜3ヶ月（2026年9〜11月想定） | SEOメディア（体験談・ノウハウ記事）+ 求人紹介LP + フォーム応募。9〜10月はSEO仕込み・企業開拓準備・LINE公式新規開設、**職業紹介許可の発行（11/2予定）後に手動取次マッチングを開始** | 学生集客CPA、応募→採用の転換率、成果報酬15万円の受容性 |
| **Phase 1: セルフサーブ化** | 3〜6ヶ月 | 学生会員登録、求人DB、応募・メッセージ、企業セルフサーブ掲載、簡易ATS、採用報告→請求 | 人を介さないマッチング成立、企業の自走掲載 |
| **Phase 2: マッチング精度向上** | 6〜12ヶ月 | 志向性診断、レコメンド、口コミ投稿の仕組み化、ツナカレID連携（個人単位登録の共通基盤） | ミスマッチ低減（1ヶ月継続率）、ツナカレ相互送客 |

> Phase 0 で「手動」なのは検証のためであり、恒常的な営業人員は置かない。
> 企業開拓はツナカレ既存接点へのメール・案内が中心（詳細は 06_growth.md）。

## 3. ユーザー定義とペルソナ

### 学生側（一次ターゲット）
- **P1: キャリア意識の芽生えた大学1〜3年生**。「何かやらないとまずい」とは思っているが、自己分析未経験。アルバイト感覚で情報収集を開始する。SNS（Instagram/TikTok/X）と検索で情報収集。
- **P2: 部活・課外活動に打ち込む学生（ツナカレ層）**。時間制約が強く週2〜3稼働・リモート可の求人を求める。ガクチカは強いが業務経験ゼロ。引退前後（3年秋〜）に一気に動く。

### 企業側
- **C1: 新卒採用も見据えて長期インターンを採るベンチャー〜中堅企業**（従業員10〜300名、東京中心+リモート可）。採用担当が兼務で、営業を受けたくない。成果報酬なら試しやすい。

### 運営側
- 事業責任者1名（兼務）。審査・請求・カスタマーサポートを1人日/週以内で回せる設計とする。

## 4. 機能要件

### 4.1 Phase 0（メディア + 手動マッチング）

| # | 機能 | 要件 |
|---|---|---|
| F0-1 | SEOメディア | 体験談・職種解説・「長期インターンとは」等の記事。静的生成、構造化データ、sitemap 自動生成（ラグビーマニアのパイプライン運用ノウハウを流用） |
| F0-2 | 求人紹介ページ | 求人を構造化フォーマット（§4.4）で記事化。1求人1URL（SEO資産化） |
| F0-3 | 学生エントリーフォーム | 氏名・大学・学年・所属（部活/サークル/団体/無所属）・希望条件・志向質問（3問程度）。LINE公式アカウント友だち追加へ誘導 |
| F0-4 | 企業掲載申込フォーム | 会社情報・求人情報・成果報酬規約への同意 |
| F0-5 | 運営オペレーション | スプレッドシート等で応募管理・企業取次・採用報告の確認・請求（開発しない） |

### 4.2 Phase 1（セルフサーブ化）

| # | 機能 | 要件 |
|---|---|---|
| F1-1 | 学生会員登録 | メール or LINE ログイン。**個人単位のアカウント**（将来ツナカレと共通ID化する前提の設計） |
| F1-2 | 学生プロフィール | 大学・学年・所属活動（部活等）・ガクチカ・希望条件・稼働可能時間 |
| F1-3 | 求人検索・詳細 | 職種 / 業界 / 週稼働日数 / リモート可否 / エリア / 「インターン採用の目的」で絞込。詳細は構造化フォーマット（§4.4） |
| F1-4 | 応募・メッセージ | 応募時に「応募理由・この求人に期待すること」の記入を必須化（ワンクリック応募にしない＝本気度を担保し、業界共通の痛点であるドタキャン・無断欠席を抑制）。応募後は企業と学生のメッセージで日程調整まで完結。通知はメール+LINE |
| F1-5 | 企業セルフサーブ | 企業アカウント登録→求人作成→運営審査→公開。応募者一覧・ステータス管理（応募/面談/内定/稼働開始/不採用）の簡易ATS |
| F1-6 | 採用報告・請求 | 企業がステータスを「稼働開始」にすると成果報酬の請求が発生。請求書自動発行（外部サービス連携可）。**学生側にも稼働開始の確認**を取り、虚偽報告・報告漏れを防ぐ |
| F1-7 | 運営管理画面 | 企業・求人の審査、通報対応、KPIダッシュボード（登録・応募・決定・売上） |

### 4.3 Phase 2（マッチング精度向上）

| # | 機能 | 要件 |
|---|---|---|
| F2-1 | 志向性診断 | 5分で完了する軽量診断（成長志向/収入志向/業界興味/働き方）。結果を求人の「目的タグ」とマッチング表示（「この求人はあなたの◯◯志向と合致」） |
| F2-2 | 口コミ・体験談投稿 | 稼働開始1ヶ月後・終了時に学生へ投稿依頼（実際に働いた学生のみ投稿可＝信頼性担保）。**評価項目は「居心地・フィット感」「質問への向き合い方・フィードバックの質」を中核に設計**（Voilの口コミ統計分析で満足度と最も相関する因子。03_insights.md §7）。求人詳細に表示。SEOコンテンツとしても資産化 |
| F2-3 | レコメンド | プロフィール・診断・行動ログからの求人推薦（初期はルールベースで十分） |
| F2-4 | ツナカレ連携 | 共通ID基盤 / 部活単位データと個人アカウントの紐付け / 3年生引退のタイミングで新卒紹介（ツナカレ）へ送客 |

### 4.4 求人構造化フォーマット（ミスマッチ解消のコア仕様）

すべての求人に以下を**必須入力**とする。ここが競合媒体との最大の差別化。

1. **インターン採用の目的**（選択式・公開）: 「新卒採用の入口として」/「即戦力として」/「両方」— 社員登用・新卒登用の実績数も記載
2. **任せる業務の具体**: 入って1ヶ月でやること / 3ヶ月後に任せたいこと（自由記述だがテンプレートで具体性を強制）
3. **ある1日のスケジュール**（インターン生の実例）
4. **働き方条件**: 週稼働日数（下限/推奨）、リモート可否、テスト期間・部活との両立可否、時給
5. **どんな学生に来てほしいか / 合わない学生**（両方書かせる）
6. **先輩インターン生の声**（Phase 2 で口コミと接続）

## 5. 非機能要件

| 項目 | 要件 |
|---|---|
| SEO | 記事・求人ページは SSG/ISR で静的配信。Core Web Vitals 良好、構造化データ（JobPosting / Article / FAQ）、OGP |
| モバイル | スマホファースト（学生流入の大半は SNS→スマホ） |
| コスト | インフラ月額 1万円以内を目標（静的ホスティング + BaaS） |
| 個人情報 | 学生の個人情報は応募先企業にのみ開示。プライバシーポリシー・利用規約整備。氏名等は応募まで企業に非開示 |
| 運用 | 週次の運営工数 1人日以内で回る自動化（審査・請求・通知） |
| 可用性 | 商用 BaaS/ホスティングの SLA に準拠（自前運用しない） |

## 6. 技術スタック（提案）

初期投資最小・SEO 最優先・1人開発（AI 併用）前提。

- **フロント/サイト**: Next.js（App Router, SSG/ISR）+ Vercel または Cloudflare Pages
- **DB/認証**: Supabase（Postgres + Auth + Row Level Security）
- **コンテンツ管理**: リポジトリ内 Markdown + フロントマター（Phase 0）→ 必要になったら headless CMS
- **通知**: メール（Resend 等）+ LINE Messaging API（学生への到達率重視）
- **請求**: 請求書発行 SaaS 連携（マネーフォワード請求書 / freee 等）またはStripe Invoicing
- **分析**: GA4 + Search Console（ラグビーマニアで導入済みの運用を流用）

> ラグビーマニアで確立した「データ→静的サイト生成→SEO」の運用資産を Phase 0 のメディア構築にそのまま転用できる。

## 7. 法務・コンプライアンス論点（実装前に要確認）

| 論点 | 内容 | 対応方針（案） |
|---|---|---|
| **有料職業紹介事業の許可** | 有給の長期インターンは雇用契約を伴うため「労働者の募集」に該当。成果報酬で学生を企業に引き合わせるモデルは、運用次第で「職業紹介」（要・厚労省許可）に該当しうる | **【解決済み】許可は2026年11月2日発行予定**。発行前（Phase 0 序盤）は媒体型（応募情報の転送のみ・選別/斡旋なし）に運用を限定し、発行後に紹介型の手動取次を解禁する |
| 労働条件明示 | 求人に時給・業務内容等の明示（職安法の労働条件明示ルール） | 求人フォーマットの必須項目で担保 |
| 未成年・学業配慮 | 深夜勤務・過度な稼働の求人を審査で排除 | 掲載ガイドライン策定 |
| 個人情報保護 | 学生情報の第三者提供（応募先企業への提供）への同意取得 | 利用規約・応募時同意で担保 |
| 成果報酬の返金規定 | 早期離脱時の返金/減額（例: 稼働開始後30日以内の離脱で50%返金） | 企業の掲載ハードルを下げつつ、ミスマッチ解消インセンティブをサービス側に持たせる |

## 8. 決定事項と残論点（2026-08-20 フィードバック反映）

### 決定済み
| 論点 | 決定内容 |
|---|---|
| 成果報酬の定義 | **稼働開始時点で15万円 + 稼働開始後30日以内の離脱で50%返金** で確定 |
| 職業紹介許可 | **2026年11月2日に発行予定**。許可発行前は媒体型（応募情報の転送のみ・選別/斡旋を行わない）で運用し、**11月2日以降に紹介型（手動取次・すり合わせ）を解禁**する。Phase 0 の9〜10月はSEO仕込み・コンテンツ制作・企業開拓準備に充て、許可発行と同時にマッチング開始するスケジュールが合理的 |
| LINE公式アカウント | **新規開設**（ツナカレ既存アカウントは使用しない） |
| 初期求人開拓の前提 | ツナカレ既存取引企業への案内は**使えるが少数・高学歴学生向けに偏る**ため、主要な開拓手段としては当てにしない（§リスク対応と 06_growth.md §5 を修正済み）。高学歴前提の求人は初期の登録学生層とミスマッチを起こしうる点に注意 |

### 残論点（調査・検討中）
1. **ブランド**: ツナカレのサブブランド方針が第一候補。ただしサブブランドにすべきかは**メリット・デメリットの比較調査の上で決定**（調査資料を別途提出）
2. **市場の空白の性質見極め**: 「口コミ専業の空白」「掲載課金の空白」等が (a) 競合がまだ入り込めていないだけなのか (b) 市場としておいしくないから誰もやらないのか、を深掘りしてから埋めにいく空白を確定する（キャリアバイト終了理由の深掘りを含む。調査資料を別途提出）
3. サービス名・ドメイン（ブランド方針決定後）
